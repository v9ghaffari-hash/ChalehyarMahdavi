# مدیریت GitHub و ساخت APK اندروید — نسخه 2.1.0

یک داشبورد فارسی و راست‌چین برای مدیریت مخازن GitHub، اجرای GitHub Actions، بررسی گزارش خطاها و دریافت Artifactها. آیکون برنامه از تصویر ارسالی شما ساخته شده است.

## امکانات برنامه

- اتصال به GitHub با Fine-grained Personal Access Token
- نمایش مخازن و شاخه‌ها
- مشاهده و اجرای Workflowهای GitHub Actions
- نمایش تاریخچه اجرا، Jobها، مراحل و لاگ خطاها
- دریافت Artifactهای Workflow و استخراج فایل APK
- مرور فایل‌ها و پوشه‌های مخزن
- بارگذاری فایل‌ها و پوشه‌ها به GitHub
- ویرایش و ذخیره مستقیم فایل‌های مخزن
- نصب به‌صورت PWA از مرورگر اندروید
- ساخت APK اندروید با GitHub Actions

## جایگزینی نسخه قبلی در مخزن فعلی

اگر این مخزن را قبلاً با ZIPهای قدیمی راه‌اندازی کرده‌ای، قبل از Push نسخه جدید، Workflowهای APK تکراری را حذف کن تا دو ساخت هم‌زمان اجرا نشوند: اگر وجود دارند، فایل‌های `.github/workflows/build-android-apk.yml` و `.github/workflows/android-apk.yml` قدیمی را حذف کن؛ سپس فایل جدید `.github/workflows/android-apk.yml` را از این بسته قرار بده. فایل `.github/workflows/pages.yml` هم باید با نسخه جدید جایگزین شود. این نسخه Pages را فقط دستی اجرا می‌کند و ساخت APK را مستقل روی هر Push به `main` انجام می‌دهد.

## رفع مشکل ذخیره APK داخل برنامه اندروید

در APKهای قبلی، دانلود با لینک Blob در WebView انجام می‌شد. WebView به‌صورت پیش‌فرض پنجره انتخاب محل ذخیره اندروید را به این لینک متصل نمی‌کند؛ بنابراین ممکن بود با لمس دانلود هیچ پنجره‌ای باز نشود. این نسخه یک افزونه بومی Capacitor به نام `NativeFileSaver` دارد که از پنجره استاندارد اندروید (`ACTION_CREATE_DOCUMENT`) استفاده می‌کند.

پس از دریافت و آماده‌سازی APK، پنجره انتخاب محل ذخیره باز می‌شود. محل دلخواه (مانند Downloads یا پوشه انتخابی در حافظه/فضای ابری) را انتخاب کن. داده‌ها به قطعه‌های کوچک نوشته می‌شوند تا از ارسال یک فایل Base64 بزرگ از WebView به اندروید جلوگیری شود. همین مسیر برای ذخیره ZIP لاگ‌های GitHub نیز استفاده می‌شود. در نسخه وب، دانلود مرورگر مثل قبل باقی می‌ماند.

**مهم:** برای دریافت این قابلیت باید APK را با Workflow جدید دوباره بسازی و نصب کنی؛ به‌روزرسانی صرفاً فایل HTML داخل مخزن، برنامه اندرویدی نصب‌شده قبلی را تغییر نمی‌دهد.

## ساخت APK اندروید

این مسیر به تنظیم GitHub Pages نیاز ندارد و مستقل از Workflow انتشار وب است.

1. فایل ZIP پروژه را استخراج کن.
2. **تمام محتویات داخل پوشه پروژه** را در ریشه مخزن GitHub خودت قرار بده؛ خود پوشه والد را به‌عنوان یک پوشه تو در تو آپلود نکن.
3. تغییرات را روی شاخه `main` ثبت و Push کن.
4. در GitHub به زبانه **Actions** برو و Workflow با نام **Build Android APK** را باز کن.
5. اجرای خودکار با Push روی `main` شروع می‌شود؛ برای اجرای دستی هم **Run workflow** را بزن.
6. پس از موفقیت، وارد همان اجرای Workflow شو و از بخش **Artifacts** فایل `github-manager-android-apk` را دانلود کن.
7. ZIP مربوط به Artifact را باز کن. فایل `github-manager-debug.apk` داخل آن APK قابل نصب است و `SHA256SUMS.txt` برای بررسی یکپارچگی فایل قرار دارد.

اگر APK ساخته نشد، در همان اجرای Workflow مرحله قرمز را باز کن و لاگ آن مرحله را بررسی کن. خطاهای Workflow وب (Pages) مانع ساخت APK نیستند.

### نکته درباره نوع APK

خروجی پیش‌فرض **Debug APK** است؛ برای نصب و آزمایش روی گوشی مناسب است، اما نسخه امضاشده Release برای انتشار رسمی در فروشگاه نیست. برای انتشار رسمی باید یک کلید امضای Release بسازی و آن را فقط در GitHub Secrets نگه داری؛ فایل keystore یا رمز آن را داخل مخزن قرار نده.

## انتشار نسخه وب (اختیاری)

Workflow انتشار وب عمداً فقط با اجرای دستی شروع می‌شود تا فعال نبودن GitHub Pages باعث شکست هر Push و گیج‌شدن گزارش‌ها نشود.

برای بار اول:

1. وارد **Settings → Pages** مخزن شو.
2. در قسمت **Build and deployment**، گزینه **GitHub Actions** را به‌عنوان Source انتخاب کن.
3. سپس وارد **Actions → Deploy PWA to GitHub Pages** شو و **Run workflow** را بزن.

خطای `Get Pages site failed - Not Found` یعنی هنوز سایت Pages برای مخزن فعال/پیکربندی نشده است. این کار یک‌بار از Settings انجام می‌شود. نیازی به تغییر Workflow ساخت APK برای حل آن خطا نیست.

پس از انتشار، آدرس Pages را با Chrome اندروید باز کن و از منوی مرورگر **Install app** یا **Add to Home screen** را انتخاب کن.

## توکن GitHub و دسترسی‌ها

برای امکانات برنامه، یک Fine-grained Personal Access Token بساز و فقط مخزن‌های موردنیاز را انتخاب کن. حداقل دسترسی‌های موردنیاز بسته به کاری که انجام می‌دهی:

| قابلیت | مجوز پیشنهادی |
|---|---|
| مشاهده اطلاعات مخزن و شاخه‌ها | Metadata: Read |
| مشاهده و اجرای Workflow، گزارش Jobها و Artifactها | Actions: Read and write |
| مرور، بارگذاری، حذف و ویرایش فایل‌ها | Contents: Read and write |
| تغییر فایل‌های Workflow در `.github/workflows` | Workflows: Read and write |

مجوزها را فقط در حد نیاز فعال کن. توکن را در کد، README، اسکرین‌شات یا فایل‌های مخزن قرار نده.

در برنامه، گزینه ذخیره توکن در مرورگر به‌صورت پیش‌فرض خاموش است. ذخیره‌سازی مرورگر رمزنگاری‌شده نیست؛ روی دستگاه مشترک فعالش نکن و پس از اتمام کار توکن را از برنامه پاک یا در تنظیمات GitHub لغو کن.

## ساخت محلی (اختیاری)

نیازمندی‌ها: Node.js 22، Java 21 و Android SDK.

```bash
npm install
npm run verify
npm run prepare:web
npx cap add android
npx @capacitor/assets generate --android
npx cap sync android
cd android
./gradlew assembleDebug
```

مسیر خروجی: `android/app/build/outputs/apk/debug/app-debug.apk`

## ساختار مهم پروژه

```text
.
├── index.html
├── manifest.webmanifest
├── sw.js
├── icons/                 # آیکون‌های PWA
├── assets/                # منابع اصلی آیکون و Splash اندروید
├── scripts/               # آماده‌سازی و بررسی پروژه
├── capacitor.config.json
└── .github/workflows/
    ├── android-apk.yml    # ساخت APK با هر Push روی main
    └── pages.yml          # انتشار وب با اجرای دستی
```

## نسخه 2.2.0 — تازه‌سازی و انتخاب پوشه اندروید

- دکمه «تازه‌سازی کل صفحه» برای بارگذاری مجدد برنامه اضافه شد؛ تنظیمات ذخیره‌شده محلی حفظ می‌شوند.
- در APK اندروید، انتخاب پوشه از طریق Android Storage Access Framework انجام می‌شود.
- فایل‌های پوشه انتخاب‌شده به‌صورت بازگشتی فهرست و هنگام آپلود به‌صورت قطعه‌ای خوانده می‌شوند.
- در مرورگرهای وب، ورودی استاندارد انتخاب پوشه همچنان فعال است.

برای دریافت این تغییرات باید APK جدید را از GitHub Actions بسازی و نصب کنی.
